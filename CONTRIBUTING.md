# Contributing to PKG Explorer

Thanks for your interest! Bug reports, ideas and pull requests are welcome.

## Getting started

```sh
git clone https://github.com/WhiteAnominum/PKG-Explorer.git
cd PKG-Explorer
python3 -m venv .venv
.venv/bin/pip install -e ".[test]"

.venv/bin/pkg-explorer            # graphical interface
.venv/bin/pkg-explorer-cli --help # command line
.venv/bin/pytest                  # tests (no game needed)
```

You do not need any PS4 package to work on the project: the tests build synthetic ones.

## How the code is organized

```
pkg_explorer/
├── pkg.py          PKG/PFS reader: header, entries, keys, PFS, file tree, extraction
├── crypto.py       RSA, AES-CBC, key derivation and AES-XTS used by pkg.py
├── sfo.py          param.sfo parser
├── keys.py         RSA key sets      ┐ generated by tools/gen_tables.py
├── entry_names.py  entry id -> name  ┘ from the shadPS4 sources (do not edit)
├── cli.py          pkg-explorer-cli (info, list, extract, integrate)
├── i18n.py         English -> Portuguese translations
├── desktop.py      Linux integration: .pkg file type, menu shortcut, icons
├── shadps4.py      where a PKG goes when installed in shadPS4 (reads shadPS4's config)
├── kde_dnd.py      KDE drag-and-drop protocol (extract straight into the drop folder)
├── util.py         small shared helpers
├── data/           icons and the MIME type definition
└── gui/            graphical interface (Qt / PySide6)
    ├── __init__.py main()
    ├── window.py   main window and its actions
    ├── tree.py     file list, dragging items out
    ├── model.py    tree model (sorting, filtering)
    └── extraction.py extraction thread and progress dialog
tests/
├── pkgbuilder.py   builds synthetic fake PKGs (the reverse of pkg.py)
└── test_*.py
packaging/          AppImage and Flatpak recipes, desktop file, AppStream metadata
tools/              maintenance scripts
docs/FORMAT.md      the PKG/PFS format as the reader uses it
```

If you are going to touch `pkg.py`, read [docs/FORMAT.md](docs/FORMAT.md) first: it explains
the offsets and structures the code refers to.

## Guidelines

- **Tests:** run `pytest` before sending a change and add tests for new behavior. To test the
  reader with specific content (including malicious or malformed packages), build a PKG with
  `tests/pkgbuilder.py` (see the `make_pkg` fixture in `tests/conftest.py`).
- **Style:** the project uses [ruff](https://docs.astral.sh/ruff/). Run
  `ruff format . && ruff check .` (both run in CI).
- **Language:** code, comments and commit messages in English are preferred. User-visible texts
  are written in English inside `_("...")` and translated in `pkg_explorer/i18n.py`;
  `tests/test_i18n.py` fails if a translation is missing or unused.
- **Security:** names, sizes and offsets inside a PKG come from untrusted files. New parsing code
  must validate them (see `check_name`, `_safe_target` and the limits at the top of `pkg.py`)
  and raise `PkgError` instead of crashing. `tests/test_security.py` has examples, including
  fuzzing.
- **Qt threads:** Qt objects are only created and used in the GUI thread. The extraction runs in
  a plain Python thread that never touches Qt: it only updates an `ExtractionState`, which the GUI
  thread polls with a timer (see `gui/extraction.py`). Do not use `QThread` or cross-thread
  signals; Qt objects used from another thread crash at random, often without any warning. Start
  extractions only through `MainWindow._extract`, which allows one at a time and cancels and
  waits for the worker before the window closes. `tests/test_threads.py` checks these rules, and
  the tests fail on any Qt thread warning.
- **Generated files:** do not edit `keys.py` or `entry_names.py` by hand; regenerate them with
  `python3 tools/gen_tables.py <path to a shadPS4Plus checkout>`.

## Pull requests

1. Fork the repository and create a branch for your change.
2. Keep the change focused; describe what it does and how you tested it.
3. Make sure `pytest` and `ruff check .` pass. GitHub Actions runs both on every pull request.

## Reporting bugs

Open an [issue](https://github.com/WhiteAnominum/PKG-Explorer/issues) with the PKG Explorer
version (menu ☰ → About), how you installed it (AppImage, Flatpak or source), your distribution
and desktop, and the steps to reproduce. Please do **not** attach game files or links to them.

For security problems (for example, a PKG that makes PKG Explorer write outside the destination
folder), please describe the issue without publishing a working malicious file.
